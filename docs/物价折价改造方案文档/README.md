# 物价折价改造方案文档阅读顺序

## 推荐阅读顺序

建议按编号从 `01` 看到 `07`。

如果时间有限，至少先看：

1. `01-项目分析-物价折价改造.md`
2. `02-统一计价规则中心建设方案.md`
3. `03-稳定性审查与优化建议.md`
4. `07-开发任务清单-物价折价改造.md`

## 文档说明

| 顺序 | 文件 | 适合谁看 | 主要用途 |
| --- | --- | --- | --- |
| 01 | `01-项目分析-物价折价改造.md` | 需求、开发、项目负责人 | 先搞清楚这单到底要做什么，避免把它误当成页面小改 |
| 02 | `02-统一计价规则中心建设方案.md` | 架构、后端、负责人 | 看总体架构，明确为什么要做统一规则中心和统一计价服务 |
| 03 | `03-稳定性审查与优化建议.md` | 后端、测试、运维、负责人 | 看钱账风险控制，重点是并发占额、三段式确认、审核、回滚、异常兜底 |
| 04 | `04-Oracle表设计草案.md` | 后端、DBA | 看 Oracle 11g 表结构、规则条件/动作/版本/追溯/占额表设计 |
| 05 | `05-统一计价接口设计.md` | 后端、HIS、自助机、公众号开发 | 看统一接口、试算、确认、提交、取消、冲正、追溯查询 |
| 06 | `06-每日对账与异常核查设计.md` | 财务、运维、测试、后端 | 看凌晨自动对账、异常明细、财务报表和处理闭环 |
| 07 | `07-开发任务清单-物价折价改造.md` | 开发、测试、项目负责人 | 看实际任务拆分和推进顺序 |

## 不同角色怎么读

## 需求和项目负责人

建议重点看：

- `01-项目分析-物价折价改造.md`
- `02-统一计价规则中心建设方案.md`
- `03-稳定性审查与优化建议.md`
- `07-开发任务清单-物价折价改造.md`

重点关注：

- 这不是单纯前端字段改造。
- 真实范围包括 HIS、自助机、公众号统一计价。
- 钱账风险主要在并发、落账失败、退费冲正、规则误发布。

## 后端开发

建议重点看：

- `02-统一计价规则中心建设方案.md`
- `03-稳定性审查与优化建议.md`
- `04-Oracle表设计草案.md`
- `05-统一计价接口设计.md`

重点关注：

- 规则条件、规则动作、公式执行器。
- `confirm -> commit/cancel` 三段式。
- `PR_LIMIT_OCCUPY` 和 `PR_LIMIT_LOCK`。
- 试算和确认必须分开。
- 所有折价必须能追溯。

## 前端和 HIS 界面开发

建议重点看：

- `01-项目分析-物价折价改造.md`
- `05-统一计价接口设计.md`
- `07-开发任务清单-物价折价改造.md`

重点关注：

- 折价页签维护字段。
- 特殊项目弹窗。
- 试算和确认调用差异。
- 计价结果和折价原因展示。

## 自助机和微信公众号开发

建议重点看：

- `02-统一计价规则中心建设方案.md`
- `05-统一计价接口设计.md`
- `03-稳定性审查与优化建议.md`

重点关注：

- 各端不再自己写折价逻辑。
- 特殊项目必须调用统一计价服务。
- 服务异常时不能自行按普通价格收费。

## 财务和物价管理人员

建议重点看：

- `01-项目分析-物价折价改造.md`
- `06-每日对账与异常核查设计.md`
- `03-稳定性审查与优化建议.md`

重点关注：

- 为什么价格变化能回查。
- 每日折价汇总报表。
- 异常明细报表。
- 规则发布审核和回滚。

## 测试人员

建议重点看：

- `03-稳定性审查与优化建议.md`
- `05-统一计价接口设计.md`
- `06-每日对账与异常核查设计.md`
- `07-开发任务清单-物价折价改造.md`

重点关注：

- 金额一致性。
- 并发确认。
- 退费冲正。
- 规则版本切换。
- 每日对账异常识别。

## 最短阅读路径

如果只想快速抓重点，按这个顺序：

1. 看 `01`，明白业务范围。
2. 看 `02`，明白为什么要统一规则中心。
3. 看 `03`，明白怎么避免出钱账问题。
4. 看 `07`，明白怎么排任务。
