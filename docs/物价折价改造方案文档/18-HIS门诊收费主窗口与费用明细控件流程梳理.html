HIS 门诊收费主窗口与费用明细控件流程梳理

这页按实际运行对象、事件触发顺序、关键数据对象和最终落账边界来拆旧代码。目标是看完以后能说清楚：界面从哪里来、患者怎么选中、未结算明细怎么进表格、金额怎么回写、收费最终在哪里落账。

主窗口：ucCharge.cs 患者控件：珠海 ucPatientInfo 明细控件：珠海 ucDisplay 资金边界：Fee.cs

1. 一眼结论

主窗口只是容器和编排层。
`ucCharge` 自己不画患者输入区和费用明细表，它通过接口和参数加载各个控件，再把它们嵌入不同区域。
费用明细表来自珠海 `ucDisplay`。
关键链路是 `MZ0084` -> `IOutpatientItemInputAndDisplay` -> `ucDisplay` -> `plMain.Controls.Add(...)`。
界面金额不是最终资金边界。
`ucDisplay` 做预览和表格金额，最终 confirm/commit/cancel 在 `Fee.cs` 的 `ClinicFee` 落账链路。

最短主链路

输入门诊号/卡号
  -> 珠海 ucPatientInfo.tbCardNO_KeyDown()
  -> InputedCardAndEnter
  -> ucCharge.registerControl_InputedCardAndEnter()
  -> ucShowPatients 查询并选择 Register
  -> ucCharge.ucShow_SelectedPatient(register)
  -> QueryChargedFeeItemListsByClinicNO(register.ID)
  -> registerControl.FeeDetails 分组
  -> itemInputControl.ChargeInfoList
  -> 珠海 ucDisplay.SetChargeInfo()
  -> SumCost() 刷新左右金额并回写患者控件
  -> SaveFee()
  -> popFeeControl_FeeButtonClicked()
  -> feeIntegrate.ClinicFee(... ChargeTypes.Fee ...)
  -> Fee.cs confirm / HIS 写库 / commit 或 cancel

2. 主窗口控件组成

当前收费窗口可以理解成一个壳，里面按区域挂了患者信息、费用明细、发票预览、金额汇总、支付弹窗和外屏。

plTop：患者信息区 `registerControl` = 珠海 `ucPatientInfo` 负责门诊号/卡号输入、挂号记录、处方序号、费用分组。
左侧：发票预览 `leftControl` = 主工程 `ucInvoicePreview` 负责发票号校验、票据预览、收费后刷新。
plMain：费用明细表 `itemInputControl` = 珠海 `ucDisplay` 负责未结算明细显示、手工录入、数量/金额调整、折价预览。
右侧：金额汇总 `rightControl` = 主工程 `ucCostDisplay` 显示总额、自费、医保、公费、支付变化，并同步外屏。
支付弹窗和外围接口 `popFeeControl` = 珠海 `frmDealBalance`，`iBankTrans` = `frmBankTrans`，`iMultiScreen` = 外屏 `frmMiltScreen`。
字段 接口 当前运行时实例 职责

itemInputControl IOutpatientItemInputAndDisplay Neusoft.SOC.Local.OutpatientFee.ZhuHai.Zdwy.IOutpatientItemInputAndDisplay.ucDisplay 中间费用明细表、项目录入、金额汇总、折价/统一计价预览。

5. 选择挂号后加载未结算费用

真正把未结算明细加载进费用表格的入口是 `ucCharge.ucShow_SelectedPatient(register)`。

设置患者上下文

registerControl.PatientInfo = register，itemInputControl.PatientInfo = register，右侧控件刷新患者信息。

查询未结算明细

outpatientManager.QueryChargedFeeItemListsByClinicNO(register.ID) 根据挂号流水号查未收费明细。

患者控件分组

registerControl.FeeDetails setter 按 RecipeSequence 分组，生成 FeeDetailsSelected。

推给明细控件

itemInputControl.ChargeInfoList = registerControl.FeeDetailsSelected，珠海 ucDisplay 开始显示表格。

ucShow_SelectedPatient(register)
  -> registerControl.PatientInfo = register
  -> rightControl.SetInfomation(..., "4")
  -> itemInputControl.PatientInfo = register
  -> feeItemLists = QueryChargedFeeItemListsByClinicNO(register.ID)
  -> registerControl.FeeDetails = feeItemLists.Clone()
  -> registerControl.SetChargeInfo()
  -> registerControl.FeeDetailsSelected
  -> itemInputControl.ChargeInfoList = registerControl.FeeDetailsSelected
关键理解： `ucCharge` 查询到的是当前挂号下全部未结算明细；`ucPatientInfo` 再按处方序号分组并决定当前选中哪一组；`ucDisplay` 只展示当前选中的 `ChargeInfoList`。

6. 珠海 `ucDisplay` 的显示和回写闭环

`ucDisplay` 不是单纯展示控件。它会计算金额、刷新左右控件，并把修改后的明细反向同步给患者控件。

1

ChargeInfoList setter

保存 alChargeInfo，关闭单元格变化处理，调用 SetChargeInfo()，再恢复事件处理。

2

SetChargeInfo()

清空表格，处理旧折价或 PricingAgent 预览，遍历 FeeItemList，写入 FarPoint 行，并把真实对象放到 Rows[row].Tag。

3

SumCost()

调用 GetFeeItemList() 计算当前表格金额，刷新 rightControl 和 leftControl，再触发 FeeItemListChanged(alCharge)。

4

主窗口回写患者控件

ucCharge.itemInputControl_FeeItemListChanged() 把修改后的明细写给 registerControl.ModifyFeeDetails，再调用 DealModifyDetails() 重新汇总处方金额。

registerControl.FeeDetailsSelected
  -> itemInputControl.ChargeInfoList
  -> ucDisplay.SetChargeInfo()
  -> ucDisplay.SumCost()
  -> rightControl.SetInfomation(...)
  -> leftControl.RefreshDisplayInfomation(...)
  -> FeeItemListChanged(alCharge)
  -> ucCharge.itemInputControl_FeeItemListChanged(al)
  -> registerControl.ModifyFeeDetails = al.Clone()

7. 手工录入项目流程

8. 确认收费主流程

`SaveFee()` 是收费前的准备和支付弹窗阶段；真正落账在支付弹窗点击收费后的 `popFeeControl_FeeButtonClicked()`。

SaveFee() 做什么

校验患者、校验明细、取发票号、医保上传和预结算、金额汇总、生成发票数据、打开支付弹窗。

popFeeControl_FeeButtonClicked() 做什么

收到弹窗确认收费后，写 HIS 收费数据、医保结算、提交事务、打印发票和导诊单、调用收费后扩展接口、清屏。

最终落账分段

popFeeControl_FeeButtonClicked(balancePays, invoices, invoiceDetails, invoiceFeeDetails)
  -> 开启事务
  -> 连接医保接口
  -> feeIntegrate.ClinicFee(... ChargeTypes.Fee ...)
  -> 医保上传/结算/提交
  -> HIS 事务 Commit
  -> 打印发票、导诊单、电子票据
  -> afterFee.AfterFee(comFeeItemLists, "0")
  -> Clear()
不要把 `SaveFee()` 理解成已经收费成功。 `SaveFee()` 只是把收费前校验、医保预结算、发票拆分、支付弹窗都准备好。只有支付弹窗触发 `FeeButtonClicked` 并且 `ClinicFee`、医保、事务提交都成功后，才算最终收费成功。

10. 统一计价和旧折价边界

物价折价改造要分清两个层次：界面预览层和最终资金层。

界面预览层：珠海 `ucDisplay`
加载医生明细、手工录入项目、修改数量/金额时，可以实时试算并把预览金额写回表格。这里适合提示收费员，但不是最终资金边界。
最终资金层：`Fee.cs`
`ClinicFee` 生成稳定发票组合号和处方明细号后做 confirm；HIS 写库成功后 commit；失败或回滚时 cancel。

11. 事件和数据线

旧代码难读的原因之一，是界面靠事件和属性传递对象。梳理时盯住下面几条线。

线索 发送方 接收方 业务意义
InputedCardAndEnter 珠海 ucPatientInfo ucCharge.registerControl_InputedCardAndEnter() 患者卡号/门诊号回车后通知主窗口。
SelectedPatient ucShowPatients ucCharge.ucShow_SelectedPatient() 挂号选择完成，主窗口开始加载未结算明细。
FeeDetails ucCharge 珠海 ucPatientInfo 把挂号下全部未结算明细交给患者控件分组。
ChargeInfoList ucCharge 珠海 ucDisplay 把当前选中的处方组明细交给中间表格展示。
FeeItemListChanged 珠海 ucDisplay ucCharge.itemInputControl_FeeItemListChanged() 表格金额或明细变化后，回写患者控件重新汇总处方金额。
FeeButtonClicked 珠海 frmDealBalance ucCharge.popFeeControl_FeeButtonClicked() 支付弹窗确认收费，主窗口进入最终落账。
ChargeButtonClicked 珠海 frmDealBalance ucCharge.popFeeControl_ChargeButtonClicked() 支付弹窗内选择划价保存，走 SaveCharge()。

三个最重要的数据对象

Register

患者和挂号上下文。由挂号选择窗口返回，贯穿患者控件、明细控件、医保和收费落账。

FeeItemList

收费明细对象。医生未结算明细和手工录入项目最终都会变成它。

Balance / BalancePay

发票、结算和支付对象。由 `SaveFee()` 生成并交给支付弹窗，最终落账使用。

12. 排查清单

后续梳理或排 bug 时，可以直接按问题类型走下面的检查点。

问题：没有加载珠海费用明细控件 先查控制参数 MZ0084 是否指向 SOC.Local.OutpatientFee.ZhuHai.dll|...IOutpatientItemInputAndDisplay.ucDisplay；再查 DLL 是否在 HIS 运行目录。
问题：输入门诊号后没有弹挂号选择 查 ucPatientInfo.tbCardNO_KeyDown() 是否触发 InputedCardAndEnter；再查 registerControl_InputedCardAndEnter() 是否给 ucShow.CardNO 赋值。
问题：弹窗里看不到未收费标识 查 ucShowPatients 内部的 QueryChargedFeeItemListsByClinicNO(patient.ID) 返回值；注意这里仅用于标绿辅助，不是最终加载明细的位置。
问题：选择挂号后中间费用表为空 查 ucShow_SelectedPatient() 中 QueryChargedFeeItemListsByClinicNO(register.ID) 是否返回明细；再查 registerControl.FeeDetailsSelected 是否为空；最后查 ucDisplay.ChargeInfoList setter。
问题：金额显示不对或左右金额不同步 查 ucDisplay.SumCost() 是否触发，是否调用 rightControl.SetInfomation、leftControl.RefreshDisplayInfomation 和 FeeItemListChanged。
问题：界面预览金额和最终落账金额不一致 分层排查：界面先看 ucDisplay 的 PricingAgent 预览和旧折价逻辑；最终落账看 Fee.cs 的 confirm 结果和 HIS 写库后 commit/cancel。
问题：点击确认收费后失败 先分清失败发生在 SaveFee() 前置校验、医保预结算、支付弹窗，还是 popFeeControl_FeeButtonClicked() 的最终写库/医保结算/事务提交。
