# 自助机门诊待缴费用入口流程梳理

## 0. 快速结论

自助机入口不是人工门诊窗口，也不是直接复用 `CTMRFeeRule.GetFeeItemList`。当前源码路径是：

```text
ZZSB.asmx
  -> Patientopb.GetGetPrescriptionAndChargeDetailsForSRM(xml)
  -> CTMRFeeRule.GetFeeItemListnew(patientId, feeItems)
```

`GetFeeItemListnew` 是自助机专用分支。它保留组套金额汇总，但旧数量折价代码已注释，当前源码未见比例折价执行。因此自助机当前口径是不执行特殊折价。

## 1. 分析范围

| 文件 | 作用 |
| --- | --- |
| `legacy-code/zzsb/His.Service/His.Service/ZZSB.asmx.cs` | 自助机 WebService 入口。 |
| `legacy-code/zzsb/His.Service/His.Business/ZZSB/Patientopb.cs` | 自助机业务入口，解析 XML、查询待缴费用、返回 XML。 |
| `legacy-code/HIS/ZDWY.SpecialRule/ZDWY.SpecialRule.Price/CTMRFeeRule.cs` | 旧特殊规则 DLL，自助机调用 `GetFeeItemListnew`。 |

## 2. 待缴费用查询流程

```text
ZZSB.asmx
  -> GetGetPrescriptionAndChargeDetailsForSRM(xml)
       1. 解析入参 XML，读取 PATIENTID
       2. 查询该就诊记录当前可缴费用
       3. 校验处方类型、库存、自助机不可缴项目
       4. new ZDWY.SpecialRule.Price.CTMRFeeRule()
       5. CTMRFeeRule.GetFeeItemListnew(PATIENTID, al)
       6. 对指定项目做本地价格调整
       7. GetPrescriptionAndChargeDetailsForSRMXML(actualAll)
```

关键点：

- `Patientopb.cs` 确实创建了 `CTMRFeeRule`。
- 但调用的是 `GetFeeItemListnew`，不是人工门诊的 `GetFeeItemList`。
- 自助机返回的是待缴费用 XML，实际收费落账需看后续自助机付款接口是否调用 HIS `ClinicFee`。

## 3. 旧折价状态

根据校正版代码位置文档和当前源码检索，自助机分支结论如下：

| 项 | 结论 |
| --- | --- |
| 数量限制折价 | `GetFeeItemListnew` 中相关代码被注释，当前不执行。 |
| 比例折价 | 当前源码未见 `SetDiscountfee/ConvertDiscountfee` 调用。 |
| 组套 | 会展开后把子项金额汇总回主项。 |
| 与人工门诊一致性 | 不一致。人工门诊会执行旧折价，自助机当前不执行。 |

## 4. 与新折价架构的关系

当前 `Fee.cs ClinicFee(...)` 已经接入门诊统一计价 confirm/commit/cancel。因此，如果自助机后续付款落账最终调用同一个 `feeIntegrate.ClinicFee(...)`，并且自助机服务运行目录部署了 `pricing-agent.config`，就可能在实际落账时开始执行统一计价。

这会改变当前源码行为，因为自助机旧待缴查询阶段是不折价的。

## 5. 接入策略

自助机不能默认按人工门诊规则接入，必须先确认业务口径：

| 业务决策 | 技术处理 |
| --- | --- |
| 自助机迁移后也要执行特殊折价 | 自助机待缴展示和实际付款都接统一计价，`SourceSystem` 建议使用 `ZZSB`，规则条件显式包含该渠道。 |
| 自助机继续保持旧口径不折价 | 不在自助机运行目录部署 PricingAgent，或在规则条件中排除 `SourceSystem = ZZSB`。 |
| 待缴展示不折价、付款才折价 | 不建议。患者看到的金额和扣款金额可能不一致。 |

## 6. 后续改造落点

如果业务确认自助机需要执行统一计价，建议按两层改造：

1. 待缴查询层：`Patientopb.GetGetPrescriptionAndChargeDetailsForSRM` 返回前调用 `simulate`，让自助机展示金额与规则中心一致。
2. 付款落账层：确认自助机付款接口最终调用 `ClinicFee` 后，由 `Fee.cs` 的 confirm/commit/cancel 作为资金边界。

## 7. 当前结论

自助机入口已完成源码流程梳理，但不建议直接改代码接入统一计价。它属于业务口径未确认入口，已在 `docs/迁移缺口与测试用例清单.md` 的 G-02 标记为 P0。
