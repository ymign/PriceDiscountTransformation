## 批次八：第一阶段执行器实现

**目标：** 3 个执行器 + 限额占用逻辑完成

**交付物：**

### 8.1 时间窗口限制执行器 `ApplyTimeWindowLimitExecutor`
- [ ] 从 PARAMS_JSON 读取 `windowMinutes`(默认120) 和 `limitQty`
- [ ] 按 BUSINESS_CHARGE_TIME 计算窗口 [chargeTime - windowMinutes, chargeTime]
- [ ] 查询 PR_LIMIT_OCCUPY 窗口内已占用数量（STATUS IN CONFIRMED, PENDING）
- [ ] 已占用 + 本次 > limitQty → 超出部分的 finalQty 被截断
- [ ] 生成 TRACE_STEP 日志

### 8.2 金额上限执行器 `ApplyMaxAmountExecutor`
- [ ] 从 PARAMS_JSON 读取 `maxAmount`
- [ ] finalAmount = min(calculatedAmount, maxAmount)
- [ ] 生成 TRACE_STEP 日志

### 8.3 固定比例递增执行器 `IncrementPercentExecutor`
- [ ] 从 PARAMS_JSON 读取 `rate`
- [ ] totalAmount = unitPrice × (qty × rate + (1 - rate))
- [ ] 生成 TRACE_STEP 日志

### 8.4 超出部分折价为零 `DiscountExceedToZeroExecutor`
- [ ] 配合时间窗口/数量限制，超出部分金额设为 0
- [ ] discountAmount = originalAmount - finalAmount
- [ ] 生成 TRACE_STEP 日志

### 8.5 限额占用服务 `LimitOccupyService`
- [ ] `LimitKeyGenerator` — 按 04 文档 LIMIT_KEY 格式生成键
- [ ] `LimitLockService` — PR_LIMIT_LOCK 按需创建 + SELECT FOR UPDATE
  - 插入锁行，捕获唯一键冲突后重新查询
  - TIME_WINDOW 类型需枚举所有覆盖的小时桶，按字典序锁定
- [ ] 窗口累计查询 SQL（04 文档第 8.1 节）
- [ ] 占用写入 PR_LIMIT_OCCUPY

### 8.6 权威单价校验
- [ ] 从 fin_com_undruginfo 读取 unitPrice
- [ ] 与渠道传入值比对，不一致返回 PRICE_MISMATCH

### 8.7 规则缓存
- [ ] `RuleCacheService` — 内存缓存已发布规则
  - 启动时预热
  - 发布/停用/回滚时失效
  - 缓存粒度：按 ITEM_CODE 索引

**验证标准：**
- 单元测试：CT 平扫数量 5，窗口限制 3 → finalQty=3, discountQty=2
- 单元测试：浅表肿物数量 3，rate=0.5 → 400 元
- 单元测试：变应原皮肤试验费金额 500 → 封顶 440
- 单元测试：同一患者 2 小时内第 4 次 CT 平扫 → 超出折为 0
- 集成测试：验证 SELECT FOR UPDATE 锁定行为
