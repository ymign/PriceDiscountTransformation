# 测试计划

## 1. 文档目的

本文定义统一计价规则中心的测试策略、测试范围、测试场景和验收标准，确保系统在资金安全、规则正确性、并发控制和流程完整性方面满足生产要求。

本文覆盖单元测试、集成测试、端到端测试和性能测试四个层次。

---

## 2. 测试策略概述

### 2.1 测试分层

| 层次 | 目标 | 工具 | 执行频率 |
|------|------|------|----------|
| 单元测试 | 验证单个执行器、评估器、工具类的正确性 | xUnit + Moq | 每次提交 |
| 集成测试 | 验证完整业务流程（含数据库读写） | xUnit + TestContainers 或真实 Oracle | 每日构建 |
| 端到端测试 | 基于历史 74 条规则验证计算结果 | HTTP 调用 + 数据库断言 | 规则上线前 |
| 性能测试 | 验证并发吞吐量和响应时间 | k6 / wrk | 上线前 |

### 2.2 测试原则

- **资金安全用例优先：** 幂等性、额度控制、退费释放、金额取整等资金相关用例必须 100% 覆盖。
- **边界值覆盖：** NULL vs 0、数量刚好等于限额、金额刚好等于封顶、时间窗口边界等。
- **可追溯性：** 每个测试用例必须能关联到具体的规则族或业务约束。
- **独立性：** 每个测试用例必须独立，不依赖执行顺序，测试前后清理数据。

## 3. 单元测试范围

### 3.1 计价引擎执行器

已实现的执行器（13 个）及对应测试点：

| 执行器 | 测试点 |
|--------|--------|
| `OnceQtyLimitExecutor` | 单次数量限制：NULL 不校验、0 限制为零、正常限制、超出部分归零 |
| `DailyQtyLimitExecutor` | 日累计数量限制：跨收费动作累计、退费释放、NULL 不校验 |
| `TimeWindowLimitExecutor` | 2 小时窗口限制：窗口内累计、窗口外不计入、边界时间（1:59 vs 2:00）、退费释放 |
| `AmountCeilingExecutor` | 金额上限：NULL 不校验、金额刚好等于上限、超出上限取上限值 |
| `AmountFloorExecutor` | 金额下限：NULL 不校验、金额刚好等于下限、低于下限取下限值 |
| `IncrementPercentExecutor` | 固定比例递增公式：数量1不加收、数量N加收(N-1)次、rate=0.5/0.7 |
| `UnitConvertExecutor` | 双单位换算：不同部位换算基数、面积向上取整、换算数量固定为1 |
| `SameGroupMutexExecutor` | 同组互斥：同组内多个项目同时开立、超过限额归零 |
| `SameOperationCeilingExecutor` | 同手术封顶：同一手术多个项目累计、超出部分归零 |
| `AddChildItemExecutor` | 子项加收：主项目金额百分比、主项目不存在时的处理 |
| `ExceedToZeroExecutor` | 超出归零：超出限额部分金额设为 0，不影响未超出部分 |
| `ActionExecutorFactory` | 执行器工厂：根据 actionType 正确路由到对应执行器、未知类型抛异常 |
| `ActionExecutionPipeline` | 执行管道：按配置顺序依次执行、异常处理 |

### 3.2 条件评估器

| 评估器 | 测试点 |
|--------|--------|
| `ItemMatchEvaluator` | 项目编码精确匹配、通配符匹配、不匹配返回 false |
| `ChargeSceneMatchEvaluator` | 收费场景匹配：门诊/住院/手术/急诊、不匹配返回 false |
| `BodyPartMatchEvaluator` | 部位匹配：指定部位、未指定部位（NULL = 全部位）、多部位 |
| `TimeRangeEvaluator` | 时间范围：在生效期内、已过期、未生效、无时间限制 |

### 3.3 LimitKeyGenerator

| 测试点 | 说明 |
|--------|------|
| 维度组合 | `sourceSystem + businessRequestNo + itemCode` 生成唯一键 |
| NULL 处理 | 维度字段为 NULL 时的降级策略 |
| 一致性 | 相同输入始终生成相同 key |
| 区分度 | 不同输入生成不同 key |

### 3.4 PricingAmountRounder

| 测试点 | 说明 |
|--------|------|
| 正常取整 | 保留 2 位小数，四舍五入（如 123.456 -> 123.46） |
| 边界值 | 123.455 -> 123.46（银行家舍入 vs 四舍五入需确认） |
| 零值 | 0.00 -> 0.00 |
| 负数 | 退费场景的负金额处理 |
| 精度保留 | 中间计算不取整，仅最终结果取整 |

### 3.5 规则发布冲突校验

| 测试点 | 说明 |
|--------|------|
| 同项目同场景重叠 | 同一项目、同一场景、同一生效期内发布两套规则 -> 阻断 |
| 动作组冲突 | 同一规则版本内动作类型重复 -> 阻断 |
| 重复子项目 | 子项加收中重复引用同一子项目 -> 阻断 |
| 缺少测试用例 | 发布前未关联测试用例 -> 阻断 |
| 正常发布 | 无冲突时正常通过校验 |

### 3.6 幂等性校验

| 测试点 | 说明 |
|--------|------|
| 重复 confirm | 相同 businessRequestNo 重复 confirm -> 返回相同结果 |
| 指纹一致性 | 相同参数生成相同 REQUEST_FINGERPRINT |
| 指纹差异性 | 参数变更（如 inputQty 变化）生成不同指纹 -> 拒绝 |
| 超时重试 | confirm 超时后复用同一 businessRequestNo 重试 -> 幂等返回 |

### 3.7 退费累计校验

| 测试点 | 说明 |
|--------|------|
| 当日退费释放 | 退费数量正确释放日累计额度 |
| 部分退费 | 退费数量 + 历史已退不超过原有效收费 |
| 隔日退费重收 | 重收按重收当天重新校验额度 |
| 2 小时窗口退费 | 退费按收费时间（含重收时间）向前查 2 小时 |

## 4. 集成测试范围

集成测试需要真实数据库（Oracle 或等效环境），验证完整业务流程。

### 4.1 完整计价流程

```
simulate -> confirm -> commit
```

**测试步骤：**

1. 准备规则数据（规则头 + 条件 + 动作 + 版本 + 发布）
2. 调用 simulate 接口，验证返回金额正确
3. 调用 confirm 接口，验证额度占用、请求日志、折价明细写入
4. 调用 commit 接口，验证状态流转为已结算

**断言：**

- simulate 不写入 LIMIT_OCCUPY
- confirm 对特殊项目写入 LIMIT_OCCUPY，状态为 PENDING；普通项目只写折价明细用于 commit 对账
- commit 将 OCCUPY 和 CHARGE_DISCOUNT_DETAIL 状态更新为 CONFIRMED
- CHARGE_REQUEST_LOG 各阶段状态正确流转
- CHARGE_TRACE_STEP 记录完整计算步骤
- CHARGE_DISCOUNT_DETAIL 写入折价明细

### 4.2 取消流程

```
confirm -> cancel
```

**测试步骤：**

1. 调用 confirm 占用额度
2. 调用 cancel 释放额度

**断言：**

- LIMIT_OCCUPY 状态更新为 RELEASED
- CHARGE_REQUEST_LOG 状态更新为 CANCELLED
- 额度恢复（再次 confirm 可成功）

### 4.3 退费流程

```
commit -> reverse
```

**测试步骤：**

1. 完成 confirm -> commit 流程
2. 调用 reverse 退费

**断言：**

- CHARGE_REVERSE_LOG 写入退费记录
- 日累计额度正确释放
- 2 小时窗口额度正确释放
- 部分退费后额度状态正确

### 4.4 过期清理

**测试步骤：**

1. 创建 CONFIRM_PENDING 状态的记录，设置创建时间为超过阈值
2. 触发 ExpireCleanupService

**断言：**

- 超时记录状态更新为 EXPIRED
- 对应 LIMIT_OCCUPY 释放
- 正常记录不受影响

### 4.5 批量试算

**测试步骤：**

1. 构造包含多个项目的批量请求，其中部分项目存在同组互斥关系
2. 调用 batch-simulate

**断言：**

- 同组内互斥项目正确处理（超限归零）
- 非互斥项目独立计算
- BatchPricingContext 在组内项目间共享

## 5. 端到端测试场景

基于 `docs/物价折价规则整理.xlsx` 中 74 条历史规则，按规则族设计端到端场景。

### 5.1 2 小时时间窗限制场景

**覆盖规则：** CT/MR 平扫增强、CT 造影、彩色多普勒超声、床旁加收等 20 条（A 类）

**场景 A-1：窗口内未超限**

- 患者在 10:00 做 CT 平扫 1 个部位
- 患者在 11:00 做 CT 平扫 2 个部位
- 预期：3 个部位未超限（限额 3），全部正常计价

**场景 A-2：窗口内刚好超限**

- 患者在 10:00 做 CT 平扫 2 个部位
- 患者在 11:00 做 CT 平扫 2 个部位
- 预期：第 4 个部位超出限额，金额归零

**场景 A-3：窗口外不计入**

- 患者在 08:00 做 CT 平扫 3 个部位
- 患者在 11:00 做 CT 平扫 3 个部位（超过 2 小时窗口）
- 预期：两次独立计价，均未超限

**场景 A-4：加收项目窗口限制**

- 患者在 10:00 做 CT 平扫-薄层扫描(加收) 1 个
- 患者在 10:30 做 CT 平扫-薄层扫描(加收) 1 个
- 预期：第 2 个加收超出限额（限额 1），金额归零

### 5.2 同胎次限制场景

**覆盖规则：** 产科彩超、胎儿脐血流彩超等 5 条（B-3 类）

**场景 B-3-1：同胎次单项目**

- 孕妇单胎，开立产科 I 级彩超(单胎) 1 个
- 预期：正常计价

**场景 B-3-2：同胎次互斥生效**

- 孕妇单胎，同次开立产科 I 级彩超(单胎) + 胎儿脐血流彩超(单胎) + 胎儿大脑中动脉彩超(单胎)
- 预期：同胎次互斥组内，超过 1 个的部分金额归零

### 5.3 单项目封顶价场景

**覆盖规则：** 变应原皮肤试验费、浅表恶性肿瘤去除费等 4 条（A 类 + B-2 类）

**场景 A-5：金额未超封顶**

- 变应原皮肤试验费，单价 22 元，数量 10
- 预期：220 元，未超 440 元封顶

**场景 A-6：金额超封顶**

- 变应原皮肤试验费，单价 22 元，数量 30
- 预期：660 元 -> 封顶 440 元

**场景 B-2-1：恶性肿瘤封顶**

- 浅表恶性肿瘤去除费，单价 2000 元，数量 3
- 预期：公式计算后与 4400 元封顶比较取小值

### 5.4 按数量加收公式场景

**覆盖规则：** 浅表肿物去除费 3 条、自体皮移植费 4 条（B-1 类）

**场景 B-1-1：浅表肿物数量 1**

- 浅表肿物去除费，单价 200 元，数量 1
- 预期：200 x (1 x 0.5 + 0.5) = 200 元

**场景 B-1-2：浅表肿物数量 3**

- 浅表肿物去除费，单价 200 元，数量 3
- 预期：200 x (3 x 0.5 + 0.5) = 400 元

**场景 B-1-3：自体皮移植数量 3**

- 自体皮移植费(常规)，单价 1000 元，数量 3
- 预期：1000 x (3 x 0.7 + 0.3) = 2400 元

### 5.5 单位换算 + 单肿物封顶场景

**覆盖规则：** 巨痣去除费、血管瘤去除费、脉管畸形去除费、神经纤维瘤去除费共 24 条（B-4 类）

**场景 B-4-1：巨痣单肿物**

- 巨痣去除费，单价 546 元，面积 6 cm2
- 预期：换算数量 = 6，金额 = 546 x 6 = 3276 元，未超 4400 元封顶

**场景 B-4-2：巨痣单肿物超封顶**

- 巨痣去除费，单价 546 元，面积 10 cm2
- 预期：换算数量 = 10，金额 = 546 x 10 = 5460 元，封顶 4400 元

**场景 B-4-3：巨痣多肿物累加**

- 巨痣去除费，2 个肿物：3 cm2 + 5 cm2
- 预期：肿物1 = min(546x3, 4400) = 1638，肿物2 = min(546x5, 4400) = 2730，总计 = 4368 元

**场景 B-4-4：血管瘤分部位换算**

- 血管瘤去除费(常规)，单价 856 元，头面部 8 cm2
- 预期：换算数量 = ceil(8/4) = 2，金额 = 856 x 2 = 1712 元

**场景 B-4-5：血管瘤躯干部换算**

- 血管瘤去除费(常规)，单价 856 元，躯干部 288 cm2
- 预期：换算数量 = ceil(288/144) = 2，金额 = 856 x 2 = 1712 元

**场景 B-4-6：儿童加收**

- 巨痣去除费主项目最终金额 3276 元
- 巨痣去除费-儿童(加收)
- 预期：3276 x 30% = 982.80 元

### 5.6 皮瓣移植公式场景

**覆盖规则：** 带蒂皮瓣转移费、游离皮瓣移植费等 17 条（B-5 类）

**场景 B-5-1：面积未超基础**

- 带蒂皮瓣转移费，单价 2000 元，面积 10 cm2
- 预期：面积 <= 15，金额 = 2000 元（不加收）

**场景 B-5-2：面积超出基础**

- 带蒂皮瓣转移费，单价 2000 元，面积 30 cm2
- 预期：extraSteps = ceil((30-15)/15) = 1，金额 = 2000 x (1 + 1 x 0.15) = 2300 元

**场景 B-5-3：大面积**

- 带蒂皮瓣转移费，单价 2000 元，面积 50 cm2
- 预期：extraSteps = ceil((50-15)/15) = 3，金额 = 2000 x (1 + 3 x 0.15) = 2900 元

**场景 B-5-4：同手术封顶**

- 同一手术下带蒂皮瓣转移费 + 游离皮瓣移植费，累计金额超过同手术封顶
- 预期：超出部分归零

### 5.7 子项加收场景

**覆盖规则：** 所有"-儿童(加收)""-累及重要器官(加收)"等后缀项目

**场景 C-1：子项与主项目同 resultGroupNo**

- 主项目 confirm 成功，子项自动关联同一 resultGroupNo
- commit 时主子项目原子落账
- 子项由 HIS 生成新的 chargeDetailNo 时，仍按 itemCode、partSeq、finalQty、finalAmount 对账通过

**场景 C-2：主项目 cancel 子项联动**

- 主项目 cancel，子项的额度占用同步释放

**场景 C-3：子项金额计算**

- 主项目最终金额 1000 元，儿童加收比例 30%
- 预期：子项金额 = 1000 x 30% = 300 元

**场景 C-4：父项退费带出同组子项**

- reverse 请求只传主项目 chargeDetailNo
- 预期：计价中心按 resultGroupNo 找到同组子项，退费数量和金额按整组校验

**场景 C-5：混合普通和特殊明细 commit**

- 一次 confirm 同时包含普通项目和特殊项目
- 预期：confirm 保存全部有效费用明细；commit 必须回传全部 HIS 实落明细，缺一条或多一条均拒绝

## 6. 性能测试要求

### 6.1 响应时间要求

| 接口 | P95 响应时间 | P99 响应时间 |
|------|-------------|-------------|
| simulate | < 200ms | < 500ms |
| confirm | < 500ms | < 1000ms |
| commit | < 300ms | < 500ms |
| cancel | < 300ms | < 500ms |
| reverse | < 500ms | < 1000ms |
| special-flag | < 100ms | < 200ms |

### 6.2 并发要求

| 场景 | 并发数 | 持续时间 | 通过标准 |
|------|--------|----------|----------|
| simulate 并发 | 50 | 5 分钟 | 错误率 < 0.1% |
| confirm 并发（不同患者） | 30 | 5 分钟 | 无额度突破 |
| confirm 并发（同一患者同一项目） | 10 | 1 分钟 | 幂等正确，无重复占额 |

### 6.3 数据量要求

- 规则表数据量：> 500 条规则头，> 2000 条条件，> 2000 条动作
- 单日限额记录：> 10000 条
- 2 小时窗口查询：覆盖 > 1000 条历史记录时仍满足响应时间要求

## 8. 测试验收标准

### 8.1 单元测试

- 代码覆盖率 >= 80%
- 资金安全相关代码覆盖率 = 100%
- 所有用例通过

### 8.2 集成测试

- 所有业务流程用例通过
- 数据库状态一致性验证通过
- 异常场景（超时、并发、重复请求）处理正确

### 8.3 端到端测试

- 74 条历史规则全部完成配置化迁移验证
- 每条规则至少 1 个正向用例 + 1 个边界用例
- 计算结果与历史系统一致（允许四舍五入差异）

### 8.4 性能测试

- 满足第 6 节所有响应时间和并发要求
- 无内存泄漏（5 分钟压力测试后内存稳定）
- 无数据库连接泄漏
