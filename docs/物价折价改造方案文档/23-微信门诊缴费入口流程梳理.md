# 微信门诊缴费入口流程梳理

## 0. 快速结论

微信端当前源码没有执行旧特殊折价规则。主要链路是：

```text
RegisterInfoManager / OrderManager
  -> GetFeeItemList(...)
  -> NeusoftBussiness.MakeInvoice(...)
  -> feeIntegrate.ClinicFee(...)
```

`GetFeeItemList(...)` 只看到组套展开和普通明细生成；当前仓库源码未见 `ZDWY.SpecialRule`、`SetRestrictingfee`、`SetDiscountfee` 调用。因此微信端接入统一计价前必须先确认：迁移后是否要改变旧行为，让微信也执行特殊折价。

## 1. 分析范围

| 文件 | 作用 |
| --- | --- |
| `legacy-code/WeChat/FS.ZDWY.Internet.BP/OutPatient/RegisterInfoManager.cs` | 微信挂号/缴费主业务入口之一。 |
| `legacy-code/WeChat/FS.ZDWY.Internet.BP/OutPatient/OrderManager.cs` | 微信订单侧缴费入口。 |
| `legacy-code/WeChat/FS.ZDWY.Internet.BP/OutPatient/NeusoftBussiness.cs` | 微信端发票拆分和普通发票明细生成。 |
| `legacy-code/HIS/HISFC.BizProcess/Integrate/Fee/Fee.cs` | 如果微信最终调用 `ClinicFee` 落账，则会进入这里的门诊统一计价边界。 |

## 2. RegisterInfoManager 缴费流程

核心流程：

```text
RegisterInfoManager
  -> 查询挂号/待缴费用
  -> GetFeeItemList(al, reg, ref errMsg)
       1. 转换 HIS 门诊 FeeItemList
       2. 处理非药品组套展开
       3. 处理部分 DR/CT 去重
       4. 返回普通费用明细
  -> NeusoftBussiness.MakeInvoice(feeIntegrate, reg, comFeeItemLists, ...)
  -> feeIntegrate.ClinicFee(ChargeTypes.Fee, "C", true, reg, ...)
```

当前未见旧特殊折价调用。

## 3. OrderManager 缴费流程

订单侧存在另一条相似链路：

```text
OrderManager
  -> GetFeeItemList(al, reg, ref errMsg)
  -> NeusoftBussiness.MakeInvoice(...)
  -> feeIntegrate.ClinicFee(...)
```

不能只查 `RegisterInfoManager`。如果微信要接统一计价，订单侧也要纳入同一口径。

## 4. MakeInvoice 的角色

`NeusoftBussiness.MakeInvoice(...)` 负责：

- 发票拆分。
- 生成发票主表对象。
- 生成发票明细对象。
- 返回 `ClinicFee` 所需的发票和费用集合。

它不是折价规则入口，当前不承载特殊折价逻辑。

## 5. 与新折价架构的关系

如果微信最终落账调用的是 `feeIntegrate.ClinicFee(...)`，那么 `Fee.cs` 的门诊统一计价 confirm/commit/cancel 可以覆盖实际资金边界。

但仍有两个问题：

1. 微信旧源码不折价，接统一计价会改变历史价格口径。
2. 微信展示/预结算阶段当前没有调用 `simulate`，如果只在 `ClinicFee` 前 confirm，可能出现展示金额与实际扣款金额不一致。

## 6. 接入策略

| 业务决策 | 技术处理 |
| --- | --- |
| 微信迁移后执行特殊折价 | 微信查询待缴费用时增加 `simulate`，付款落账继续走 `ClinicFee` confirm/commit/cancel，`SourceSystem` 建议使用 `WECHAT`。 |
| 微信继续保持旧口径不折价 | 不在微信服务运行目录部署 PricingAgent，或规则条件排除 `SourceSystem = WECHAT`。 |
| 仅 HIS 人工窗口折价 | 规则条件限定 `SourceSystem = HIS_WY` 或限定收费场景。 |

## 7. 当前结论

微信入口已完成源码流程梳理，但不建议在未确认业务口径前直接启用统一计价。它已在 `docs/迁移缺口与测试用例清单.md` 的 G-03 标记为 P0。
