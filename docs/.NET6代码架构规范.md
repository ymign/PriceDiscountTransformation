# .NET 6 代码架构规范

> 基于 Microsoft 官方设计指南 | 强调：开闭原则、简洁原则、易维护

---

## 一、核心设计原则

### 1.1 开闭原则（OCP）

**对扩展开放，对修改关闭**

```
需求变化时 → 新增代码 → 不修改现有代码
```

**实现方式**：

| 方式 | 说明 | 示例 |
|------|------|------|
| 抽象接口 | 定义稳定接口，实现可替换 | `IPushHandler` → 多种业务实现 |
| 策略模式 | 行为可配置切换 | 重试策略、限流策略 |
| 工厂模式 | 创建逻辑集中管理 | `PushHandlerFactory.Get(bizType)` |
| 配置化 | 行为参数化，不改代码 | 限流阈值、超时时间配置 |

**正确示例**：

```csharp
// ✅ 新增业务类型：只加一个类，不改框架代码
public sealed class ExamPushHandler : IPushHandler
{
    public string BizType => "exam";
    
    public Task<string> BuildSnapshotJsonAsync(string taskId)
    {
        // 检查申请的特定逻辑
    }
}

// 框架自动发现并注册
services.Scan(scan => scan
    .FromAssemblyOf<IPushHandler>()
    .AddClasses(classes => classes.AssignableTo<IPushHandler>())
    .AsImplementedInterfaces()
    .WithSingletonLifetime());
```

**错误示例**：

```csharp
// ❌ 每次新增业务都要改这里
public string BuildJson(string bizType, string taskId)
{
    if (bizType == "exam") { ... }
    else if (bizType == "lab") { ... }
    else if (bizType == "order") { ... }  // 新增要改这里
    // 无限增长...
}
```

### 1.2 简洁原则（KISS）

**保持简单，避免过度设计**

```
能简单解决 → 不引入复杂抽象
三层够用 → 不建七层
一个类够用 → 不拆五个
```

**判断标准**：

| 问题 | 简洁方案 | 过度设计 |
|------|----------|----------|
| 3 种业务类型 | 3 个实现类 | 抽象工厂 + 建造者 + 策略组合 |
| 配置读取 | `IOptions<T>` | 自定义配置中心 + 热更新 + 版本管理 |
| 日志记录 | `ILogger` | 自定义日志框架 + 多输出 + 格式化引擎 |

**正确示例**：

```csharp
// ✅ 简洁：直接解决问题
public async Task<int> ClaimTasksAsync(string bizType, int batchSize)
{
    const string sql = @"
        UPDATE push_task 
        SET status = '队列中', claim_batch_id = :batchId
        WHERE status = '待推送' AND biz_type = :bizType
        AND ROWNUM <= :batchSize";
    
    return await _db.ExecuteAsync(sql, new { bizType, batchSize, batchId = Guid.NewGuid().ToString("N") });
}
```

**错误示例**：

```csharp
// ❌ 过度设计：层层包装
public async Task<int> ClaimTasksAsync(string bizType, int batchSize)
{
    var criteria = new TaskCriteriaBuilder()
        .WithBizType(bizType)
        .WithBatchSize(batchSize)
        .WithStatus(TaskStatus.Pending)
        .Build();
    
    var strategy = _claimStrategyFactory.Create(bizType);
    var result = await strategy.ExecuteAsync(criteria);
    
    return _resultMapper.MapToInt(result);
}
```

### 1.3 易维护原则

**代码要容易理解和修改**

```
新人能看懂 → 一周能上手 → 改一处不崩全局
```

**维护性指标**：

| 指标 | 标准 | 检查方法 |
|------|------|----------|
| 类大小 | < 300 行 | IDE 统计 |
| 方法大小 | < 30 行 | IDE 统计 |
| 方法参数 | ≤ 4 个 | 编译警告 |
| 嵌套层级 | ≤ 3 层 | 代码审查 |
| 依赖数量 | ≤ 5 个 | 构造函数参数 |

## 二、项目结构

### 2.1 最简三层架构

```
HisDataPush/
├── src/
│   ├── HisDataPush.Core/           # 核心层（无外部依赖）
│   │   ├── Models/                 # 数据模型
│   │   ├── Interfaces/             # 接口定义
│   │   ├── Enums/                  # 枚举
│   │   └── Options/                # 配置选项类
│   │
│   ├── HisDataPush.Infrastructure/ # 基础设施层
│   │   ├── Repositories/           # 数据访问实现
│   │   ├── Messaging/              # 消息队列实现
│   │   └── External/               # 外部服务实现
│   │
│   └── HisDataPush.Producer/       # 应用层（入口）
│       ├── Services/               # 业务服务
│       └── Program.cs              # 启动入口
│
└── tests/
    └── HisDataPush.Tests/          # 测试
```

### 2.2 依赖方向

```
Producer → Infrastructure → Core
   ↓           ↓             ↓
（入口）    （实现）       （定义）

箭头方向 = 依赖方向 = 稳定方向
```

**规则**：
- Core 最稳定，不依赖任何外部
- Infrastructure 实现 Core 的接口
- Producer 组合使用 Infrastructure

### 2.3 文件夹与命名空间对应

```
文件路径                           命名空间
HisDataPush.Core/Models/PushTask.cs → HisDataPush.Core.Models
HisDataPush.Core/Interfaces/       → HisDataPush.Core.Interfaces
```

## 三、命名规范

### 3.1 基本规则

| 类型 | 规则 | 示例 |
|------|------|------|
| 类 | PascalCase | `PushTask`, `TaskRepository` |
| 接口 | I + PascalCase | `IPushTaskRepository` |
| 方法 | PascalCase + 动词 | `GetByIdAsync`, `ClaimTasksAsync` |
| 属性 | PascalCase | `TaskId`, `BizType` |
| 私有字段 | _ + camelCase | `_logger`, `_repository` |
| 参数 | camelCase | `taskId`, `bizType` |
| 常量 | PascalCase | `MaxBatchSize` |

### 3.2 有意义的命名

```csharp
// ✅ 好：一眼懂
public async Task ClaimPendingTasksAsync(string bizType, int batchSize)
public bool IsPushComplete { get; }
public int RetryCount { get; }

// ❌ 差：要猜
public async Task Claim(string bt, int cnt)
public bool Flag { get; }
public int Count { get; }
```

### 3.3 避免缩写

```csharp
// ✅ 好
string businessType
int retryCount
CancellationToken cancellationToken

// ❌ 差
string bt
int cnt
CancellationToken ct  // 除非极常用如 id、url
```

## 四、类设计规范

### 4.1 单一职责

**一个类只做一件事**

```csharp
// ✅ 好：职责单一
public sealed class PushTaskRepository
{
    // 只负责 push_task 表的数据操作
    public Task<PushTask?> GetByIdAsync(string id);
    public Task<int> ClaimPendingTasksAsync(string bizType, int batchSize);
    public Task UpdateStatusAsync(string id, string status);
}

// ❌ 差：职责混杂
public sealed class PushService
{
    public Task<PushTask?> GetTask(string id);           // 数据访问
    public Task<int> ClaimTasks(string bizType);         // 数据访问
    public Task PublishToQueue(PushTask task);           // 消息队列
    public Task CallPlatform(PushTask task);             // HTTP调用
    public void WriteLog(string message);                // 日志
}
```

### 4.2 类成员顺序

```csharp
public sealed class PushTask
{
    // 1. 常量
    public const int MaxRetryCount = 10;
    
    // 2. 静态字段/方法
    private static readonly string[] ValidStatuses = { "待推送", "已推送" };
    
    // 3. 实例字段
    private int _retryCount;
    
    // 4. 构造函数
    public PushTask(string id, string bizType)
    {
        Id = id;
        BizType = bizType;
    }
    
    // 5. 属性
    public string Id { get; }
    public string BizType { get; }
    public string Status { get; private set; }
    
    // 6. 公共方法
    public void MarkAsPushed()
    {
        Status = "已推送";
    }
    
    // 7. 私有方法
    private bool CanChangeStatus(string newStatus)
    {
        return ValidStatuses.Contains(newStatus);
    }
}
```

### 4.3 接口设计

**接口要小而专注**

```csharp
// ✅ 好：接口职责单一
public interface IPushTaskRepository
{
    Task<PushTask?> GetByIdAsync(string id);
    Task<IReadOnlyList<PushTask>> ClaimPendingTasksAsync(string bizType, int batchSize);
}

public interface IMessagePublisher
{
    Task PublishAsync(PushMessage message);
}

// ❌ 差：接口过大
public interface IPushService
{
    Task<PushTask?> GetTask(string id);
    Task Publish(PushTask task);
    Task CallPlatform(PushTask task);
    Task UpdateStatus(PushTask task);
    Task Retry(PushTask task);
}
```

### 4.4 依赖注入

```csharp
// ✅ 好：构造函数注入，依赖清晰
public sealed class ProducerWorker
{
    private readonly IPushTaskRepository _repository;
    private readonly IMessagePublisher _publisher;
    private readonly ILogger<ProducerWorker> _logger;
    
    public ProducerWorker(
        IPushTaskRepository repository,
        IMessagePublisher publisher,
        ILogger<ProducerWorker> logger)
    {
        _repository = repository;
        _publisher = publisher;
        _logger = logger;
    }
}

// ❌ 差：服务定位器，依赖隐藏
public sealed class ProducerWorker
{
    private readonly IServiceProvider _services;
    
    public ProducerWorker(IServiceProvider services)
    {
        _services = services;
    }
    
    public async Task RunAsync()
    {
        var repository = _services.GetRequiredService<IPushTaskRepository>(); // 隐藏依赖
    }
}
```

## 五、方法设计规范

### 5.1 方法长度

**一个方法不超过 30 行**

```csharp
// ✅ 好：方法简短，职责清晰
public async Task<int> RunPollingCycleAsync(string bizType)
{
    var backlog = await GetQueueBacklogAsync(bizType);
    if (backlog > Threshold)
    {
        return 0;
    }
    
    var tasks = await ClaimTasksAsync(bizType);
    foreach (var task in tasks)
    {
        await PublishAsync(task);
    }
    
    return tasks.Count;
}

// ❌ 差：方法过长，难以理解
public async Task RunAsync()
{
    // 100+ 行代码...
    // 各种逻辑混杂...
}
```

### 5.2 参数数量

**不超过 4 个参数，超过则封装为对象**

```csharp
// ✅ 好：参数少
public async Task<PushTask?> GetByIdAsync(string id)

// ✅ 好：多参数封装为请求对象
public async Task<IReadOnlyList<PushTask>> ClaimPendingTasksAsync(ClaimTasksRequest request)

public sealed class ClaimTasksRequest
{
    public string BizType { get; init; } = string.Empty;
    public int BatchSize { get; init; } = 100;
    public string ClaimBatchId { get; init; } = string.Empty;
}

// ❌ 差：参数过多
public async Task<IReadOnlyList<PushTask>> ClaimPendingTasksAsync(
    string bizType, 
    int batchSize, 
    string claimBatchId, 
    string status, 
    DateTime? startTime, 
    DateTime? endTime)
```

### 5.3 返回值设计

```csharp
// ✅ 好：明确返回类型
public Task<PushTask?> GetByIdAsync(string id);              // 可能不存在用 nullable
public Task<IReadOnlyList<PushTask>> GetAllAsync();          // 列表用 IReadOnlyList
public Task<bool> ExistsAsync(string id);                    // 存在性用 bool
public Task<int> UpdateStatusAsync(string id, string status); // 影响行数用 int

// ❌ 差：返回类型模糊
public Task<object> GetData(string id);    // 什么类型？
public Task<List<PushTask>> GetAllAsync(); // 可修改，不安全
```

## 六、异步编程规范

### 6.1 基本规则

```csharp
// ✅ 异步方法以 Async 结尾
public Task<PushTask?> GetByIdAsync(string id);
public Task<int> ClaimTasksAsync(string bizType);

// ✅ 所有 I/O 操作使用异步
await connection.OpenAsync();
await command.ExecuteReaderAsync();
await _publisher.PublishAsync(message);

// ❌ 混用同步异步
connection.Open();                        // 同步
await command.ExecuteReaderAsync();       // 异步
```

### 6.2 CancellationToken

```csharp
// ✅ 所有异步方法接受 CancellationToken
public async Task<PushTask?> GetByIdAsync(
    string id, 
    CancellationToken cancellationToken = default)
{
    await using var connection = new OracleConnection(_connectionString);
    await connection.OpenAsync(cancellationToken);
    // ...
}

// ✅ 后台服务正确处理取消
protected override async Task ExecuteAsync(CancellationToken stoppingToken)
{
    while (!stoppingToken.IsCancellationRequested)
    {
        await RunCycleAsync(stoppingToken);
        await Task.Delay(TimeSpan.FromSeconds(30), stoppingToken);
    }
}
```

### 6.3 避免常见错误

```csharp
// ❌ async void（仅事件处理器可用）
public async void DoWorkAsync()  // 异常无法捕获

// ✅ async Task
public async Task DoWorkAsync()

// ❌ 不等待
public async Task RunAsync()
{
    DoWorkAsync();  // 没等待，异常丢失
}

// ✅ 正确等待
public async Task RunAsync()
{
    await DoWorkAsync();
}
```

```csharp
    if (string.IsNullOrWhiteSpace(bizType))
    {
        throw new ArgumentException("业务类型不能为空", nameof(bizType));
    }

```

### 7.2 异常类型选择

| 场景 | 异常类型 |
|------|----------|
| 参数为 null | `ArgumentNullException` |
| 参数无效 | `ArgumentException` |
| 状态不允许操作 | `InvalidOperationException` |
| 资源不存在 | `KeyNotFoundException` |
| 外部服务失败 | 自定义业务异常 |

### 7.3 Result 模式（推荐）

**业务逻辑用 Result，不用异常**

```csharp
// ✅ 好：Result 模式，无异常开销
public sealed class PushResult
{
    public bool IsSuccess { get; init; }
    public string? ErrorMessage { get; init; }
    
    public static PushResult Success() => new() { IsSuccess = true };
    public static PushResult Fail(string error) => new() { IsSuccess = false, ErrorMessage = error };
}

public async Task<PushResult> PushAsync(PushTask task)
{
    if (task.Status != "待推送")
    {
        return PushResult.Fail("任务状态不允许推送");
    }
    
    var response = await CallPlatformAsync(task);
    return response.IsSuccess 
        ? PushResult.Success() 
        : PushResult.Fail(response.ErrorMessage);
}

// 使用
var result = await PushAsync(task);
if (!result.IsSuccess)
{
    _logger.LogWarning("推送失败：{Error}", result.ErrorMessage);
}
```

### 12.2 新增重试策略

```csharp
// 步骤 1：定义策略接口
public interface IRetryStrategy
{
    TimeSpan GetDelay(int retryCount);
}

// 步骤 2：实现策略
public sealed class ExponentialBackoffStrategy : IRetryStrategy
{
    public TimeSpan GetDelay(int retryCount)
    {
        return TimeSpan.FromSeconds(Math.Pow(2, retryCount));
    }
}

// 步骤 3：配置选择
services.AddSingleton<IRetryStrategy, ExponentialBackoffStrategy>();
```
