# 物价折价规则中心上线前必须执行清单

> 本清单是上线阻断清单，不是建议项。任意一项未完成、未验证或结果不符合预期，禁止把特殊项目收费切到新规则中心。
>
> 金额规则以旧 HIS 正式环境为准。当前已确认旧 HIS 口径为：先执行 `Restrictingfee` 数量限制/互斥，再执行 `FIN_DISCOUNT_FEE` 比例折价，最后执行 `TOPPRICE` 封顶。

## 0. 使用原则

- [ ] 上线负责人必须逐项打勾，并记录执行人、执行时间、数据库实例、应用版本、验证结果截图或日志。
- [ ] 本清单所有 SQL 必须在生产同构环境或生产库上线窗口内执行验证，不能只用开发库结果替代。
- [ ] 任何金额差异、规则数量不一致、动作顺序不一致、执行器未命中、对账异常，都必须先停上线，定位清楚后再继续。
- [ ] 不允许为了上线临时关闭特殊项目规则后按普通项目收费。特殊项目服务不可用时，必须走安全策略。

## 3. 动作执行顺序必须对齐旧 HIS

必须验证 `PR_DICT`：

```sql
SELECT dict_code, sort_no, remark
FROM PR_DICT
WHERE dict_type = 'ACTION_TYPE_ORDER'
ORDER BY sort_no;
```

必须顺序：

| 动作 | 顺序 | 说明 |
|---|---:|---|
| `CONVERT_QTY` | 10 | 双单位换算 |
| `APPLY_DAY_LIMIT_QTY` | 20 | 日数量限制 |
| `APPLY_TIME_WINDOW_LIMIT` | 30 | 时间窗口数量限制 |
| `APPLY_ONCE_LIMIT_QTY` | 40 | 单次数量限制 |
| `SAME_GROUP_MUTEX` | 50 | 同组互斥 |
| `FORMULA_CALC` | 60 | 公式/比例折价 |
| `APPLY_MIN_AMOUNT` | 70 | 金额下限 |
| `APPLY_MAX_AMOUNT` | 80 | 金额上限/TOPPRICE |
| `SAME_OPERATION_CEILING` | 85 | 同手术封顶 |
| `ADD_CHILD_ITEM` | 90 | 子项加收 |
| `DISCOUNT_EXCEED_TO_ZERO` | 100 | 超限归零兜底 |

必须执行：

```sql
SELECT CASE
         WHEN MAX(CASE WHEN dict_code = 'APPLY_TIME_WINDOW_LIMIT' THEN sort_no END)
              < MAX(CASE WHEN dict_code = 'FORMULA_CALC' THEN sort_no END)
          AND MAX(CASE WHEN dict_code = 'FORMULA_CALC' THEN sort_no END)
              < MAX(CASE WHEN dict_code = 'APPLY_MAX_AMOUNT' THEN sort_no END)
          AND MAX(CASE WHEN dict_code = 'APPLY_MAX_AMOUNT' THEN sort_no END)
              < MAX(CASE WHEN dict_code = 'DISCOUNT_EXCEED_TO_ZERO' THEN sort_no END)
         THEN 'OK'
         ELSE 'ERROR'
       END AS action_order_check
FROM PR_DICT
WHERE dict_type = 'ACTION_TYPE_ORDER'
  AND dict_code IN (
    'APPLY_TIME_WINDOW_LIMIT',
    'FORMULA_CALC',
    'APPLY_MAX_AMOUNT',
    'DISCOUNT_EXCEED_TO_ZERO'
  );
```

必须结果：

- [ ] `action_order_check = OK`。
- [ ] `APPLY_TIME_WINDOW_LIMIT < FORMULA_CALC < APPLY_MAX_AMOUNT < DISCOUNT_EXCEED_TO_ZERO`。

阻断条件：

- [ ] `FORMULA_CALC` 排在数量限制前，禁止上线。
- [ ] `APPLY_MAX_AMOUNT` 排在 `FORMULA_CALC` 前，禁止上线。
- [ ] `DISCOUNT_EXCEED_TO_ZERO` 不是最后兜底，禁止上线。

### 4.2 DF_ 规则导入结果

必须执行：

```sql
SELECT COUNT(*) AS discount_fee_rule_count
FROM PR_RULE_HEADER
WHERE RULE_CODE LIKE 'DF_%'
  AND STATUS = 'PUBLISHED'
  AND IS_ENABLED = 'Y';
```

必须结果：

- [ ] `discount_fee_rule_count` 与 `FIN_DISCOUNT_FEE` 有效源数据数量一致。

必须执行：

```sql
SELECT h.RULE_CODE,
       COUNT(CASE WHEN a.ACTION_TYPE = 'FORMULA_CALC' THEN 1 END) AS has_formula_calc,
       COUNT(CASE WHEN a.ACTION_TYPE = 'APPLY_MAX_AMOUNT' THEN 1 END) AS has_max_amount,
       COUNT(CASE WHEN a.ACTION_TYPE = 'APPLY_MIN_AMOUNT' THEN 1 END) AS unexpected_min_amount
FROM PR_RULE_HEADER h
LEFT JOIN PR_RULE_ACTION a ON a.RULE_ID = h.RULE_ID AND a.VERSION_NO = h.CURRENT_VERSION
WHERE h.RULE_CODE LIKE 'DF_%'
GROUP BY h.RULE_CODE
ORDER BY h.RULE_CODE;
```

必须结果：

- [ ] 每条 `DF_` 规则 `has_formula_calc = 1`。
- [ ] 每条 `DF_` 规则 `unexpected_min_amount = 0`。
- [ ] `has_max_amount` 只允许由 `TOPPRICE > 0` 产生。

阻断条件：

- [ ] `DF_` 规则缺少 `FORMULA_CALC`，禁止上线。
- [ ] 从 `FIN_DISCOUNT_FEE` 生成了 `APPLY_MIN_AMOUNT`，禁止上线。
- [ ] `TOPPRICE > 0` 的项目没有 `APPLY_MAX_AMOUNT`，禁止上线。

## 5. 旧 HIS 金额口径必须做样例验证

### 5.1 必须验证的核心顺序

旧 HIS 入口重点参考：

- [ ] `legacy-code/HIS-Use/SOC.Local.OutpatientFee.ZhuHai/Zdwy/IOutpatientItemInputAndDisplay/ucDisplay.cs`
- [ ] `legacy-code/HIS-Use/ZDWY.SpecialRule/ZDWY.SpecialRule.Price/Restrictingfee.cs`

必须确认新规则中心结果等价：

```text
输入数量
-> Restrictingfee 数量限制/互斥后得到 FinalQty
-> FIN_DISCOUNT_FEE 使用限制后的 FinalQty 做比例折价
-> TOPPRICE 对比例折价后的金额做封顶
-> 超限部分按 0 元兜底
```

### 5.2 必须通过的金额样例

样例 1：数量限制后再折价

```text
单价 = 100
输入数量 = 3
时间窗口剩余额度 = 2
DISCOUNT_RATE = 0.5
TOPPRICE = 空或 0

旧 HIS 口径：
先限制数量：FinalQty = 2
再比例折价：100 * 1 + 100 * 0.5 * (2 - 1) = 150

必须结果：
FinalQty = 2
FinalAmount = 150
禁止结果 = 200
```

样例 2：全超限不能被公式抬回金额

```text
单价 = 100
输入数量 = 3
时间窗口剩余额度 = 0
DISCOUNT_RATE = 0.5

必须结果：
FinalQty = 0
FinalAmount = 0
```

样例 3：TOPPRICE 最后封顶

```text
单价 = 100
输入数量 = 3
DISCOUNT_RATE = 0.5
TOPPRICE = 120

先比例折价：100 * 1 + 100 * 0.5 * (3 - 1) = 200
再 TOPPRICE 封顶：120

必须结果：
FinalAmount = 120
```

阻断条件：

- [ ] 新规则中心任何样例结果与旧 HIS 口径不一致，禁止上线。
- [ ] 发现公式使用原始输入数量而不是限制后的 `FinalQty`，禁止上线。

## 7. 执行器与公式配置必须核对

必须确认：

- [ ] `FORMULA_CALC` 动作的 `ExecutorCode` 能找到实际执行器。
- [ ] 未注册、拼错、大小写不一致的 `ExecutorCode` 必须报错，不能静默跳过。

- [ ] `IncrementPercentExecutor` 使用限制后的 `FinalQty`，不是原始输入数量。
- [ ] 全超限 `FinalQty = 0` 时，公式不能重新生成非 0 金额。

阻断条件：

- [ ] 任意公式动作没有实际执行器处理，禁止上线。
- [ ] 日志中出现未找到执行器、动作跳过但计价成功，禁止上线。

## 8. HIS 集成必须核对

必须确认 HIS 端流程：

- [ ] 录入收费项目后，先判断是否特殊项目。
- [ ] 特殊项目必须进入规则中心计价或安全策略，不能直接按普通价格收费。
- [ ] `simulate` 只试算，不占额度。
- [ ] `confirm` 才占用额度，且业务号必须支持幂等重试。
- [ ] HIS 结算成功后必须调用 `commit`。
- [ ] HIS 取消收费或收费失败后必须调用 `cancel`。
- [ ] 退费/冲正必须调用 `reverse` 或等价补偿流程。
- [ ] `confirm` 单价不一致时必须返回或处理 `PRICE_MISMATCH`，不得继续收费。

阻断条件：

- [ ] HIS 特殊项目判断接口异常时按普通项目收费，禁止上线。
- [ ] `confirm` 成功但 HIS 失败后没有 `cancel` 补偿，禁止上线。
- [ ] 不能保证业务号幂等，禁止直接放开生产收费。

## 9. 灰度与回滚必须先演练

必须执行灰度策略：

- [ ] 第一阶段只做影子模式或小范围灰度，不直接全量切换。
- [ ] 灰度项目必须逐笔抽查旧 HIS 逻辑与规则中心输出。
- [ ] 灰度期间每天做金额对账，差异未清零前不得扩大范围。

必须确认回滚边界：

- [ ] 只有 `rollbackMode = LEGACY_EQUIVALENT` 的项目允许自动回旧逻辑。
- [ ] `NEW_SERVICE_ONLY` 或未确认等价的特殊项目，不能因为全局开关关闭就按普通价格收费。
- [ ] 全局回滚后仍必须先判断项目回滚模式。

阻断条件：

- [ ] 回滚演练未完成，禁止上线。
- [ ] 回滚方案会把特殊项目降级成普通计价，禁止上线。

## 10. 监控与上线后对账必须准备

### 10.1 上线当天必须盯的异常

必须配置或人工盯守：

- [ ] `PRICE_MISMATCH`。
- [ ] 未找到执行器或 `ExecutorCode` 无人处理。
- [ ] `action_order_check` 异常。
- [ ] `DF_` 导入数量异常。
- [ ] `CONFIRM_PENDING` 长时间未 `commit/cancel`。
- [ ] 计价接口超时、失败率上升。
- [ ] 规则中心金额与 HIS 落账金额差异。

阻断条件：

- [ ] 没有对账或监控手段，禁止上线。
- [ ] 上线当天出现资金差异且无法解释，必须暂停扩大灰度。

### 10.2 上线后第一天必须对账

必须核对：

- [ ] 规则中心 `FinalAmount` 与 HIS 实际落账金额一致。
- [ ] 规则中心 `FinalQty` 与 HIS 实际收费数量一致。
- [ ] 折价明细、追溯步骤、HIS 收费明细可以按业务号串起来。
- [ ] `confirm`、`commit`、`cancel`、`reverse` 状态闭环正确。
- [ ] 退费释放额度符合旧 HIS 口径。

阻断条件：

- [ ] 对账差异未解释，禁止继续扩大灰度。
- [ ] 出现占额未释放或重复占额，必须暂停相关项目。
