## 一、折价流程（校正）

### 1.1 门诊收费 ✅ 基本正确

原文描述基本准确，补充细节：
1. 入口 → `ucDisplay.GetFeeItemList`，内部调用 `CTMRFeeRule.GetFeeItemList(clincCode, feeArryList)`
2. SetRestrictingfee 在 `CTMRFeeRuleDB.cs` 中实现，Item.cs 中的版本是同名包装
3. 进入数量折价的条件是 `returnRows > 0` **且** `部门编码 != "7021"`（挂号部排除）
4. 比例折价在数量折价之后执行，两者可以并存
5. **`SetChargeInfo` 调用的 `ConvertRestrictingfeeCharge`**：专门处理组套类型，将组套拆开后逐明细折价，再累计回主项

### 1.2 门诊划价收费 ✅ 正确

与门诊收费流程一致，入口方法为 `SetItem`。

### 1.3 住院收费 ✅ 正确，补充细节

住院终端确认走 `ConvertRestrictingfeeZY`，只有数量折价，**无比例折价**（ucInpatientConfirm.Save 中未调用 SetDiscountfee）。

### 1.4 住院医技批费 ⚠️ 部分有误

**原文说只有比例折价**，但根据代码 `ucInpatientCharge.cs` 的 `SetItemProperty` 也调用了 `SetRestrictingfee`，医技批费**同时支持数量折价和比例折价**。

### 2.2 自助机端 ❌ 重要错误

| 原文说明 | 校正 |
|---------|------|
| "CTMRFeeRule.GetFeeItemList：走折价方法，与 HIS 窗口方法位置相同" | ❌ **严重错误**。自助机实际调用的是 `CTMRFeeRule.GetFeeItemListnew`（不是 GetFeeItemList），该方法中所有折价步骤（数量折价和比例折价）**全部被注释掉**，自助机不执行任何折价规则 |
| Item.cs SetRestrictingfee/SetDiscountfee | ❌ 自助机不调用这两个方法（GetFeeItemListnew 中已注释） |

**校正后的自助机逻辑**：
```
Patientopb.GetFeeItemList
  └─ CTMRFeeRule.GetFeeItemListnew
       ├─ 组套展开后汇总费用到主项（只返回主项，不返回明细）
       └─ 所有折价处理代码均被注释 → 自助机按原价收费，不折价
```

## 五、与新系统的映射关系（校正）

| 现有实现 | 新系统对应 | 校正 |
|---------|-----------|------|
| SetRestrictingfee（数量折价判断） | RuleMatchService + ItemMatchEvaluator | ✅ 逻辑等价 |
| SetDiscountfee（比例折价判断） | RuleMatchService + ItemMatchEvaluator | ✅ 逻辑等价 |
| ConvertRestrictingfee（明细数量折价） | TimeWindowLimitExecutor + DailyQtyLimitExecutor | ✅ 逻辑等价，**但数据源不同**（新系统查 PR_LIMIT_OCCUPY，旧系统查实际收费表） |
| ConvertRestrictingfeeCharge（组套数量折价） | HIS 端展开后逐项 confirm | ⚠️ 不是 AddChildItemExecutor，展开责任在 HIS 客户端 |
| ConvertDiscountfee（比例折价） | IncrementPercentExecutor + AmountCeilingExecutor | ✅ 公式数学等价，**无 AmountFloorExecutor（旧系统无最低限价）** |
| getRestrictingfee（2小时查询） | TimeWindowLimitExecutor + LimitOccupyRepository | ✅ 逻辑等价，**上线当天需数据迁移** |
| Restrictingfee 常数 | PR_RULE_CONDITION（ITEM_MATCH 条件） | ✅ |
| RestrictingfeeZT 常数 | PR_ITEM_GROUP + PR_ITEM_GROUP_DETAIL | ✅ |
| FIN_DISCOUNT_FEE 表 | PR_RULE_ACTION（FORMULA_CALC + APPLY_MAX_AMOUNT） | ✅ 每行拆成两条 action |
| 三端各自入口 | 统一 /api/pricing/calculate/* | ⚠️ **自助机折价迁移需业务确认**（旧系统不折价） |
