## 一、折价流程

### 1.1 门诊收费

1. 门诊收费输入门诊号选取挂号信息
2. 进入 `Neusoft.SOC.Local.OutpatientFee.ZhuHai.Zdwy.IOutpatientItemInputAndDisplay.ucDisplay` 文件，调用 `GetFeeItemList` 方法获取价格
3. 进入 `Neusoft.HISFC.BizLogic.Fee.Item.cs` 文件，调用 `SetRestrictingfee` 方法，获取是否为数量折价，获取最大折价数量，如非数量折价项目获取 returnRows 为 0，不进入数量折价逻辑
4. 进入 `Neusoft.HISFC.BizLogic.Fee.Item.cs` 文件，调用 `SetDiscountfee` 方法，获取比例折价类型、折价比例及最高限价。注意：旧表没有最低限价字段
5. 获取折价标识，标识不为 0、不为体检科室、不为多发伤患者，进入 `ConvertRestrictingfee` 方法进行数量折价，替换折价项目
6. 如为比例折价项目，进入 `ConvertDiscountfee` 方法获取比例折价及最高限价
7. 将折价项目替换原有项目用于收费
8. 进入 `Neusoft.SOC.Local.OutpatientFee.ZhuHai.Zdwy.IOutpatientItemInputAndDisplay.ucDisplay` 文件，调用 `SetChargeInfo` 方法获取页面显示价格信息，差异在这里：数量折价项目进入 `ConvertRestrictingfeeCharge` 方法，将组套信息拆分成明细进行折价，再还原给组套，其余与获取收费价格逻辑相同
9. 查询完成返回页面显示价格

### 1.2 门诊划价收费

1. 手动划价收费
2. 选择折价项目
3. 进入 `Neusoft.SOC.Local.OutpatientFee.ZhuHai.Zdwy.IOutpatientItemInputAndDisplay.ucDisplay` 的 `SetItem` 方法，进行第一遍折价
4. 进入 `Neusoft.HISFC.BizLogic.Fee.Item.cs` 的 `SetRestrictingfee`，获取是否为数量折价，获取最大折价数量，如非数量折价项目获取 returnRows 为 0，不进入数量折价逻辑
5. 进入 `Neusoft.HISFC.BizLogic.Fee.Item.cs` 的 `SetDiscountfee`，获取比例折价类型、折价比例及最高限价。注意：旧表没有最低限价字段
6. 获取折价标识，标识不为 0，不为体检科室，不为多发伤患者，进入 `ConvertRestrictingfeeCharge` 方法进行数量折价，替换折价项目
7. 如为比例折价项目，进入 `ConvertDiscountfee` 方法获取比例折价及最高限价
8. 将折价项目替换原有项目
9. 进入 `Neusoft.SOC.Local.OutpatientFee.ZhuHai.Zdwy.IOutpatientItemInputAndDisplay.ucDisplay` 文件 `GetFeeItemList` 方法获取收费价格，逻辑与门诊收费一致

### 1.3 住院收费

1. 医技划价
2. 住院终端确认查询患者进行费用确认
3. 进入 `Neusoft.HISFC.Components.Terminal.Confirm.ucInpatientConfirm.Save` 方法保存费用
4. 进入 `Item.cs` 的 `SetRestrictingfee`，获取是否为数量折价，获取最大折价数量，如非数量折价项目获取 returnRows 为 0，不进入数量折价逻辑
5. 获取折价标识，标识不为 0，进入 `ConvertRestrictingfeeZY` 方法进行数量折价，替换折价项目
6. 保存费用表收费

### 1.4 住院医技批费

1. 医技划价
2. 进入医技批费，输入患者信息，选取折价项目并保存收费
3. 进入 `Neusoft.HISFC.Components.Common.Controls.ucInpatientCharge_new.SetItemProperty` 方法获取价格信息
4. 进入 `Neusoft.HISFC.BizLogic.Fee.Item.cs` 的 `SetDiscountfee`，获取比例折价类型、折价比例及最高限价。注意：旧表没有最低限价字段
5. 根据获取比例进行折价，第一次获取价格信息，调用 `Neusoft.HISFC.Components.Common.Controls.ucInpatientCharge_new.SetItem` 获取收费价格信息，逻辑与之前保持一致，再次进入 `SetDiscountfee` 确认是否为折价项目，获取折价比例，按照折价比例完成折价处理
6. 进入 `Neusoft.HISFC.BizProcess.Integrate.FeeManager` 方法完成最终收费

## 四、现有折价逻辑分析

### 4.1 折价类型

现有系统有两种折价类型：

1. **数量折价（Restrictingfee）** — 按数量限制收费，超过最大数量后替换为折价项目
2. **比例折价（Discountfee）** — 第 1 个全价，第 2 个及以后按比例折价，并受最高限价约束。旧表无最低限价字段

### 4.2 折价处理方式

| 场景 | 数量折价方法 | 比例折价方法 |
|------|-------------|-------------|
| 门诊明细 | `ConvertRestrictingfee` | `ConvertDiscountfee` |
| 门诊组套 | `ConvertRestrictingfeeCharge` | `ConvertDiscountfee` |
| 住院明细 | `ConvertRestrictingfeeZY` | `ConvertDiscountfeeZY` |
| 退费 | — | `RetrieveReturnApply` |

### 4.3 折价标识判断条件

进入折价逻辑的前置条件：
- 折价标识不为 0
- 不为体检科室
- 不为多发伤患者

### 4.4 2小时窗口查询

`CTMRFeeRuleDB.cs` 的 `getRestrictingfee` 方法查询门诊与住院是否存在两小时内收费项目，这是现有系统中时间窗限制的实现。

### 4.5 组套折价

- 组套项目需要拆分成明细进行折价，再还原给组套
- `RestrictingfeeZT` 常数维护组套分组折价项目，同组不可一起收费
- `Astrictpackagefee` 常数维护组套中的非折价项目（豁免项）

### 4.6 三端入口差异

当前代码核对后，不能简单认为三端都复用了 HIS 的折价逻辑：
- HIS：`ucDisplay.GetFeeItemList` / `SetChargeInfo` 会进入折价逻辑
- 自助机：`CTMRFeeRule.GetFeeItemListnew` 中折价处理被注释，旧系统按原价收费
- 微信：`RegisterInfoManager.GetFeeItemList` 未发现折价调用，`OutpatientFeeSpecialRule.CTMRFeeRule` 为空壳

## 五、与新系统的映射关系

| 现有实现 | 新系统对应 |
|----------|-----------|
| `SetRestrictingfee`（数量折价判断） | `RuleMatchService` + `ItemMatchEvaluator` |
| `SetDiscountfee`（比例折价判断） | `RuleMatchService` + `ItemMatchEvaluator` |
| `ConvertRestrictingfee`（明细数量折价） | `TimeWindowLimitExecutor` + `DailyQtyLimitExecutor` |
| `ConvertRestrictingfeeCharge`（组套数量折价） | `AddChildItemExecutor` + `SameGroupMutexExecutor` |
| `ConvertDiscountfee`（比例折价） | `IncrementPercentExecutor` + `AmountCeilingExecutor`。旧系统无最低限价，不生成 `AmountFloorExecutor` |
| `getRestrictingfee`（2小时查询） | `TimeWindowLimitExecutor` + `LimitOccupyRepository` |
| `Restrictingfee` 常数 | `PR_RULE_CONDITION`（ITEM_MATCH 条件） |
| `RestrictingfeeZT` 常数 | `PR_ITEM_GROUP` + `PR_ITEM_GROUP_DETAIL` |
| `FIN_DISCOUNT_FEE` 表 | `PR_RULE_ACTION`（FORMULA_CALC 动作的 ParamsJson） |
| 三端各自入口 | 统一 `/api/pricing/calculate/*` API；自助机和微信是否纳入折价需业务确认，不能默认按 HIS 窗口旧行为迁移 |
